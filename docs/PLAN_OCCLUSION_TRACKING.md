# PLAN_OCCLUSION_TRACKING — 두 사람이 겹치거나 교차할 때 대상 구분 개선

작성: Opus 5.5 (사용자 지시로 계획 작성을 이어받음), 2026-11-15, 브랜치 `feat/occlusion-tracking`.
상태: **계획 고정(실행 전)**. 1–6절은 측정 전에 쓰고 해시를 `outputs/evidence/occlusion_tracking/prereg.json`에 남긴 뒤 바꾸지 않습니다. 결과는 7절에 덧붙입니다.

## 0. 문제와 고정 원칙

현재 `MultiTracker`(F-05 수정 이후)는 게이트 그래프의 한 성분에 트랙 또는 검출이 2개 이상이면 그 성분 전체를 AMBIGUOUS로 두고 보정하지 않습니다. 그래서 잘못된 사람에게 잠기지는 않지만(E2 700회 K3 = 0), 두 사람이 가까이 지나가면 대상이 AMBIGUOUS → STOP이 되고 다시 잠긴다는 보장이 없습니다. 위트레흐트 라이브 30 s에서 대상 LOCKED는 17 %(155/899)였고 PREDICTING이 576행이었습니다.

바꾸지 않는 원칙:
- **잘못된 사람을 따라가느니 멈춘다.** 새 기능은 "증거가 충분히 갈릴 때만" AMBIGUOUS를 해제합니다. 결정이 애매하면 지금처럼 AMBIGUOUS + STOP(`TARGET_AMBIGUOUS`).
- 만료 우선(2.0 s), 만료된 id는 되살리지 않음, LOST는 운용자가 다시 고를 때까지 유지, 선택기는 다른 사람으로 자동 전환하지 않음.
- 실기체 송신 없음(`HARDWARE_ARMED=false`, MOCK만). 모든 추론은 로컬 CPU.
- 꺼진 설정은 지금 코드와 **비트 단위로 같은 결과**를 내야 합니다(회귀 기준선).

## 1. 세 가지 축과 단계

공개 논문·알고리즘에서 알려진 방법을 우리 구조(대상 한 명, 정지 우선)에 맞게 줄여 씁니다.

### 단계 A — 연관 개선(외모 없이)
| 요소 | 알고리즘 출처 | 우리 구현 |
|---|---|---|
| 2단계 연관 | ByteTrack (Zhang et al., ECCV 2022) | 1단계는 지금과 같은 높은 점수 검출(≥ 0.35). 1단계에서 검출을 못 받은 확정 트랙만 낮은 점수 검출(0.10–0.35)과 2단계로 연결. 낮은 점수 검출은 **새 트랙을 만들지 않고**, 2단계도 1:1 또는 마진 통과일 때만 보정. |
| 관측 중심 재갱신(ORU) | OC-SORT (Cao et al., CVPR 2023) | 가림(PREDICTING/AMBIGUOUS) 뒤 처음 신뢰 관측이 오면 마지막 관측과 새 관측 사이를 직선 가상 관측으로 다시 갱신해 가림 동안 쌓인 속도 오차를 되돌림. |
| 방향 일관성(OCM) | OC-SORT | 트랙의 최근 관측 방향(Δt = 3관측)과 "마지막 관측 → 후보 검출" 방향의 각도 차를 비용에 더함(가중치 λ). |
| 박스 크기 일관성 | 단순 기하 사전 | 높이 비 `log(h_det / h_track)`의 제곱을 σ로 나눈 항을 비용에 더함. 같은 자리라도 멀고 가까운 두 사람의 박스 크기는 다름. |
| 마진 판정 | (설계) | 경합 성분에서 헝가리안 최적 배정을 구하되, 배정된 쌍마다 **비용 + 마진 ≤ 같은 트랙의 다른 후보, 같은 검출의 다른 후보** 를 둘 다 만족할 때만 신뢰. 아니면 그 쌍은 지금처럼 AMBIGUOUS. |

IMM(다중 운동 모델)은 이번 범위에서 제외합니다: 걷는 사람의 2 s 이하 가림에서는 등속 모델 + ORU로 충분한지 먼저 보고, 남은 실패가 급선회 때문이면 다음 계획에서 다룹니다(2026 ARC-SORT 보고치는 원문 확인이 안 되어 근거로 쓰지 않음).

### 단계 B — 카메라 움직임 보정(GMC)
BoT-SORT(Aharon et al., arXiv 2206.14651) 방식: 이전 프레임과 현재 프레임의 회색조 축소 영상(긴 변 ≤ 480 px)에서 검출 박스 밖의 코너(`goodFeaturesToTrack`)를 희소 광류(`calcOpticalFlowPyrLK`)로 따라가고, RANSAC 부분 아핀(`estimateAffinePartial2D`)을 추정해 예측 뒤 모든 트랙의 중심·속도·크기·공분산에 적용(P' = M P Mᵀ).
- **자동 비활성:** 코너 < 40개, RANSAC 인라이어 < 50 %, 또는 회전 > 10°/프레임·스케일 변화 > 10 %/프레임이면 그 프레임은 보정하지 않고 `gmc_skipped` 이유를 셈(하늘·물처럼 질감 없는 배경, 장면 전환).
- 프레임이 없는 입력(합성 검출)에서는 자동으로 꺼짐.

### 단계 C — 외모 재식별(ReID) 임베딩
- 모델: OSNet x0.25 (Zhou et al., ICCV 2019), Market-1501 학습 가중치, 별도 venv에서 한 번 ONNX로 변환(`scripts/export_reid_onnx.py`, 해시 고정), 실행은 프로젝트 `.venv`의 **OpenCV DNN CPU만**(torch 등 새 의존성 없음).
- 사용 범위: **경합(AMBIGUOUS) 성분의 판정과 가림 뒤 재연결에만.** 1:1 성분, 새 트랙 생성, 만료·LOST, 대상 선택에는 쓰지 않음. 만료된 id는 외모가 같아도 되살리지 않음.
- 트랙별 임베딩 EMA(α = 0.9, BoT-SORT와 같은 값), 신뢰·비경합·높은 점수 검출이며 다른 검출과 IoU < 0.3일 때만 갱신(겹친 박스는 두 사람 섞임).
- 판정: 코사인 거리를 비용에 더하고(가중치 w_app), **외모만의 마진도 같은 방향일 때만** 해제. 외모가 운동과 반대 결론을 강하게 내면(외모 마진 ≥ m_app 반대) 해제하지 않음.
- **얼굴 사용 금지:** 사람 박스의 위쪽 15 %(머리 영역)를 넣기 전에 평균색으로 지움.

## 2. 개인정보 정책(C에만 해당, 코드와 테스트로 강제)
1. 임베딩은 **프로세스 메모리에만**, 트랙 객체 안에만 있고 트랙과 함께 사라짐. `tracks.json`, `timeline.jsonl`, 리포트, 로그, 증거 파일에 임베딩·크롭을 쓰지 않음(스칼라 결정 횟수·거리 통계만). 테스트가 디스크 출력을 검사.
2. 세션(실행) 사이 동일인 매칭 금지: 임베딩 저장소·갤러리 없음. 라이브 실행에서 epoch가 바뀌면(시크·재시작) 트랙과 함께 버림.
3. 얼굴 영역 사용 금지(위 15 % 지움). 얼굴 인식·얼굴 임베딩 없음.
4. 프레임·임베딩 외부 전송 없음, 유료 API 없음.
5. **기본값은 OFF**(측정 전 결정): Market-1501은 비상업 연구용 배포이고, 신체 외모 임베딩은 개인정보(경우에 따라 생체정보)로 볼 수 있다는 분석이 있으므로, 결과와 상관없이 C는 `--reid`를 명시했을 때만 켭니다. C가 합격하면 "합격, opt-in"으로, 불합격이면 "trial"로 기록합니다.

E2X 조건(측정 전 고정, 모두 `SYNTHETIC` 표시, seed 0–49):
- **X1 같은 줄 교차**(y 간격 0, 가림 0/0.5/1.0/1.5 s): 운동만으로 가장 어려운 기하.
- **X2 겹치는 동안 점수 저하**: 두 박스 IoU > 0.3이면 뒤쪽 사람(작은 박스) 점수를 0.12–0.30으로 낮춤(실제 검출기에서 가려진 사람의 점수가 떨어지는 현상). 낮은 점수 검출은 기존 추적기에서는 버려짐.
- **X3 나란히 걷기**: A와 B가 3 s 동안 같은 방향으로 40 px 간격으로 걷다가 갈라짐.
- **X4 카메라 패닝**: 모든 사람 위치에 카메라 이동(최대 120 px/s 사인)을 더하고, GMC가 쓸 수 있게 같은 이동을 한 질감 배경 프레임을 렌더링. 사람 박스 안은 배경과 다르게 칠함.
- **X5 외모(합성)**: X1·X2에 합성 임베딩을 붙임 — `distinct`(사람별 고정 단위 벡터 + 잡음, 두 사람 코사인 거리 ≈ 0.3–0.5) / `identical`(두 사람 같은 벡터: 외모가 아무것도 구분 못 하는 경우). 실제 ReID 품질이 아니라 **판정 논리의 안전성** 시험.

MOT17 사용 방식(측정 전 고정):
- **보정용** {MOT17-02, 05, 09}, **보류(최종 판정용)** {MOT17-04, 10, 11, 13}. 파라미터는 E2와 보정용 시퀀스에서만 고르고, 보류 시퀀스는 고정한 설정으로 한 번만 돌림. 7개 합계도 함께 보고.
- 검출: 주 프로토콜은 **우리 YOLOX-nano(416, CPU, 임계값 0.10으로 낮춰 받고 추적기가 0.35/0.10으로 나눔)**. 보조로 MOT17 공개 FRCNN 검출(det.txt)도 같은 추적기에 넣어 보고(검출기 차이를 분리하기 위해).
- 지표: TrackEval(HOTA, IDF1, MOTA, IDSW) — 프로젝트 `.venv`가 아니라 별도 평가 venv에서 MOT 형식 결과 파일만 읽음. MOT17 관례대로 class 1(보행자)만, 기타 클래스는 매칭 제외.
- 출력: LOCKED/PREDICTING/AMBIGUOUS 중 **LOCKED(이번 프레임 신뢰 관측) 트랙만** 내보냄(우리 추적기가 운용자에게 "확실하다"고 말하는 상자). 모든 변형에 같은 규칙.

## 4. 비교 변형
- **V0 현재**: 지금 기본값(`assoc="strict"`, GMC 끔, ReID 끔).
- **VA**: 단계 A 전부.
- **VAB**: VA + GMC.
- **VABC**: VAB + ReID.

## 5. 합격 기준(측정 전 고정, 결과 보고 바꾸지 않음)

### 5.1 안전 관문 S (하나라도 어기면 그 변형은 FAIL)
- **S1** E2 700회: K1(가림 0.5/1.5 s 같은 id 재잠금 ≥ 95 %), K2(2.5 s 가림 LOST 100 %), K3(B에 LOCKED 0프레임) 모두 PASS. 오프센터 350회 포함 `yaw_nonzero_on_B`, `locked_while_A_hidden`, `yaw_nonzero_not_locked` = 0.
- **S2 잘못된 대상 추격률**: E2 + E2X 모든 조건에서 "대상 id가 B 위에서 LOCKED인 프레임 수"와 "B 쪽 yaw 프레임 수"가 **V0보다 늘면 FAIL**(조건별로 비교, 합계가 아니라). X5-identical에서는 V0와 같거나 적어야 함.
- **S3** 기존 테스트 전체 통과. `test_tracker_ambiguity`의 안전 의도(숨은 대상이 남의 검출을 물려받지 않음, 경합이면 STOP, LOST 고정, 2 s 만료)는 유지. 문구를 바꿔야 하면 이유를 보고하고 같은 의도의 더 엄격한 테스트로 대체.
- **S4** LOCKED가 아닐 때 yaw ≠ 0인 프레임 = 0(모든 하네스).

### 5.2 개선 관문 P (S를 통과한 변형만, 직전 채택 단계와 비교: VA는 V0, VAB는 VA, VABC는 VAB)
아래 세 가지가 **모두 나빠지지 않고**(비열등) **하나 이상이 의미 있게 좋아지면** PASS:
- **P1 교차 후 올바른 대상 유지율**(E2 + E2X, T_EVAL에 같은 id로 A 위에 있음, 조건 평균): 비열등 = −1 %p 이내, 개선 = +5 %p 이상.
- **P2 AMBIGUOUS 정지 시간**(대상이 AMBIGUOUS인 프레임 합, E2 + E2X): 비열등 = +5 % 이내, 개선 = −20 % 이상.
- **P3 ID 전환 수**: (a) E2X 정답 신원 기준 IDSW 합, (b) MOT17 보류 4개 TrackEval IDSW 합. 비열등 = 둘 다 +5 % 이내, 개선 = 둘 중 하나 −10 % 이상.
- 추가 비열등(MOT17 보류): IDF1, HOTA가 각각 −0.5 이내.
- 단계 B의 판정에서 E2/E2X 고정 카메라 조건은 GMC가 꺼지므로 P1·P2는 X4와 MOT17 이동 카메라(10, 11, 13)로 봄. 단계 C의 P1·P2는 X5-distinct와 MOT17로 봄.

### 5.3 속도 관문(기본값 ON 조건)
- 위트레흐트 30 s 원속도 라이브: 버린 프레임 ≤ 5 %, 처리 지연 p95 ≤ 33 ms. 못 맞추면 해당 단계는 opt-in으로만.
- ReID는 사람당 ms(p50/p95)와 프레임당 ms를 따로 보고.

### 5.4 판정과 기본값
- A, B: S + P + 속도 통과 시 기본 ON. 불합격이면 기본 OFF, 설정으로 켤 수 있는 trial로 남김.
- C: 2절 5항에 따라 합격해도 기본 OFF(opt-in).
- TUM·위트레흐트(정답 없음)는 판정에 쓰지 않고 보고만(위트레흐트 LOCKED 17 % 대비).

## 6. 구현·산출물
- `packages/tracking/tracker.py`: `TrackerConfig`에 `assoc("strict"|"margin")`, `low_score`, `oru`, `ocm_weight`, `size_sigma`, `margin`, `gmc`, `reid` 관련 필드. `update(t, detections, frame=None)` — frame은 GMC/ReID에만. 꺼진 설정은 현재 경로 그대로.
- `packages/tracking/gmc.py`: 희소 광류 + RANSAC 아핀, 비활성 이유.
- `packages/vision/reid.py`: OSNet ONNX 로더(해시 확인), 머리 영역 지움, 배치 추론. 임베딩은 반환값으로만.
- `packages/sim/crossing_ext.py`: E2X 조건, 정답 기반 IDSW.
- `packages/vision/mot_bench.py`: MOT17 실행(검출 캐시는 박스·점수만 — 임베딩은 캐시하지 않음), MOT 형식 내보내기.
- `scripts/fetch_models.sh`: reid 항목(해시 확인; 없으면 export 안내).
- 증거: `outputs/evidence/occlusion_tracking/`(prereg.json, e2_*, e2x_*, mot17_*, tum_*, live_*, pytest 로그, ui_smoke).
