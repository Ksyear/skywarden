## M4 (2026-11-09): real person detector + tracking panel — what was built

Commit: after `7d2072d` (see `git log`). Plan: `docs/PLAN_M4_DETECTOR_TRACKING_PANEL.md` (fable-planner); implementation by Opus 5.5. Regression: `scripts/test_all.sh` 61 -> 75 passed (`outputs/evidence/tests/pytest-20261109-003836.log`: closed_loop 1, control 13, export_and_eval 5, frame_selection 9, pipeline 6, server 11, tello 11, tracking 8, vision 11), UI smoke 26 -> 47 checks.

- `packages/vision/person_detector.py` — `YoloxDetector` (`source="REAL_MODEL"`): verifies the weights' SHA-256 against the pinned `ModelSpec` before `cv2.dnn.readNetFromONNX`; YOLOX letterbox (top-left, pad 114, BGR 0..255, no mean/std), grid decode over strides 8/16/32, person class only, `cv2.dnn.NMSBoxes`. Measures its own latency per frame (`last_ms`).
- `packages/vision/track_video.py` — offline job `python -m vision.track_video <video|image_dir> --session X [--model yolox_nano --fps 10 --max-frames 600 --score-thr 0.35 --origin ...]`; stages `LOAD_MODEL -> DETECT_TRACK -> EXPORT`, `status.json` in the same shape as map builds, SIGTERM/SIGINT -> `CANCELLED` (exit 130), writes `frames/f%06d.jpg` (long side <= 960), `tracks.json` (boxes in original pixels) and `tracking_report.json` with `MOTA/IDF1 = null`. Tracker clock is video time, not wall time. Wrapper: `scripts/run_tracking.sh <input> <session>` (forces `HARDWARE_ARMED=false DRY_RUN=true`).
- `packages/control/virtual_replay.py` — `replay_control(frames, image_width, target_id, select_k)`: yaw PID over the recorded track states for one operator-chosen id; `TargetSelector` + `YawController` reused from M3, virtual telemetry, MOCK, never transmitted (summary fields `nonzero_yaw`, `nonzero_yaw_while_not_locked`, `lost_from_k`).
- `scripts/fetch_models.sh` — downloads `yolox_nano.onnx` / `yolox_tiny.onnx` from the pinned 0.1.1rc0 release URL into `data/models/yolox/` and refuses a file whose SHA-256 differs.
- `apps/desktop/server.py` — `GET /api/models` (name, licence, input size, `available`), `GET /api/tracks`, `/api/tracks/<id>`, `/api/tracks/<id>/files/{tracks.json,tracking_report.json,status.json,frames/*}` (allow-list), `POST /api/track-jobs`, `POST /api/track-jobs/<id>/cancel`, `POST /api/tracks/<id>/control` (replay); `/api/health` reports `running_job` and `running_track_job`; one job at a time of either kind.
- `apps/desktop/static/tracking.js` (+ mode switch in `app.js`) — Mapping/Tracking switch (keys `M` / `T`, URL hash `#tracking`), canvas boxes over the frame JPEG (target accent, PREDICTING dashed, TENTATIVE dotted, raw-detections toggle), track list with keys `1`-`9` to select and `0` to clear, click a box to select, target state badge + hint, yaw bar with STOP reasons, timeline coloured by target state with the yaw trace, states loading / empty / running / failed / cancelled / disconnected.
- Differences from the plan, as implemented: `packages/control/virtual_replay.py` instead of `packages/vision/replay.py`; `tracks.json` instead of `tracks.jsonl`; `scripts/run_tracking.sh` instead of `run_tracking_job.sh`; separate `/api/track-jobs` route instead of a `kind` field on `/api/jobs`; `/control` instead of `/replay`; keys `1`-`9` instead of `1/2/3`; score threshold 0.35 (recorded in every report) instead of 0.3; onnxruntime and HOG tiers not needed (NOT_RUN); `--detector synthetic` for the tracking job is not present in `track_video.py` (the SIMULATED path remains `scripts/run_tracking_sim.sh`).
