# Plan: Mapping Quality over Job Completion (Skywarden)

Status: PLANNING. Priority switched to map quality. Own-camera capture is optional and never blocks completion. Default inputs are the already downloaded CC BY YouTube clips under `data/public/yt_*` (keep `SOURCE.md`, `.info.json`, SHA-256, `data_origin=PUBLIC_DATASET`). E4 stays NO_GO and unintegrated. `HARDWARE_ARMED=false`, `DRY_RUN=true` throughout; no hardware involved.

## 0. Baseline to beat (recorded, not assumed)
Session `outputs/maps/yt_bangkok_park_60s` (kjciube52gA, 0:30–1:30, 1831 frames @30 fps): step 10 -> 180 candidates, 4 blur, 26 dropped by the 150 cap -> 150 selected; 4 models 49/16/12/8; largest 49 (32.7 %), 10 814 points, mean reprojection 0.848 px; `status=SUCCEEDED` although `registered_ratio_ge_0.5=false`. The report is misleading: the UI shows READY for a map that covers a third of the frames.

## 1. Critique of the proposed direction, then the fix
- (a) Shot segmentation is right as a *tool*, wrong as a *diagnosis*. The brief forbids assuming edit cuts: if the cut detector finds none, the 4 models must be explained by something else (forward-only walking = low parallax, fast pans, blur runs, crowds, radial-distortion mismatch). Segmentation runs first, but the diagnosis step (D1) records which cause is actually confirmed per model boundary.
- (b) Capping by "contiguous window" changes what the map claims to cover. Allowed only if the window is declared by the user (or by the segment) *before* the run and coverage is reported against that window; auto-picking the best-behaved window is the silent exclusion the brief forbids.
- (c) Thresholds are fine as pre-declared constants, with two corrections: reprojection error is not discriminative here (0.848 px on a 33 % map), so it is a necessary, never a sufficient check; the trajectory jump test must be normalised by time gap (step / dt vs median step / dt), otherwise cap-induced uneven spacing fires false alarms.
- (d) Exporting every model is right; the UI must never offer a "merge" or draw several models in one frame of reference. Each model gets its own coordinate frame and an explicit "partial: model i of N, k/M frames" label.

## 2. Milestones (ordered; each has an exit test)
D1 Diagnose Bangkok (no code change to the pipeline). Inputs: `database.db`, `sparse/0..3`, `frames.json`, source mp4. Produce `outputs/maps/yt_bangkok_park_60s/diagnosis.json` with: (i) cut candidates on the full-rate source (HSV histogram correlation < 0.5 or mean abs diff > 40 on 64x48 grey, both required to flag; feature-overlap check: SIFT inliers between consecutive *kept* frames, flag if < 30); (ii) per model the time span of its registered frames and the inlier count across each boundary; (iii) per boundary a confirmed cause from {scene_cut, low_overlap, blur_run, pure_rotation (median inlier parallax < 1 px), dynamic_dominant (> 40 % of keypoints inside person boxes from the existing detector), none_confirmed}; (iv) effective frame spacing after the cap (max gap in seconds). Exit: every model boundary carries a cause or `none_confirmed`; the summary is copied verbatim into `docs/VALIDATION_LOG.md`. Blocked path: if pycolmap cannot read the database, re-run matching on the kept frames with the same options and note that the diagnosis is on a re-run.
D2 Input handling (`packages/mapping/shots.py`, new; `frame_selection.py` minimal change). Shot detector from D1(i) -> `shots.json` (start/end frame, duration, cut reason). Selection is per shot; sequential matching never spans a cut (one COLMAP run per shot, or one database with pairing restricted to the shot; the first is simpler and is the default). Cap rule inside a shot: if candidates > max_frames, raise step within the shot (never linspace across shots) and reject the selection if any consecutive kept pair has < 30 inliers or > 1.0 s gap; report `max_gap_s` and `min_pair_inliers`. Static-camera clips: run the detector, mark `camera_motion=static` when median flow < 0.5 px/frame, and route them to tracking; the "unsuitable for mapping" verdict must be backed by that measurement in the report. Subtitle/logo/person masks are a later option, enabled only if D1 confirms `dynamic_dominant`. Exit: Bangkok yields `shots.json`; unit test with a synthetic two-scene video splits exactly once.
D3 Quality verdict separate from job status (`sparse_pipeline.py`, report schema `map_report@2`). `status` keeps SUCCEEDED/FAILED/CANCELLED = pipeline finished and files are consistent. New `quality` block, computed on the *declared* segment: `registered_ratio >= 0.6`; `time_coverage >= 0.7` of the segment with no internal gap > 2 s; `mean_reprojection_px <= 1.5`; `models_ge_10pct == 1`; `trajectory_jumps == 0` (normalised step > 5 x median); `points3D >= 2000`. Verdict: GOOD = all pass; PARTIAL = reprojection passes and registered_ratio >= 0.3 but another check fails; POOR = otherwise. Constants live in one `QualityThresholds` dataclass, are written into the report, and are frozen in this document before any re-run. Changing them requires a new schema version and a new baseline table, never a silent edit. Exit: Bangkok re-evaluated offline from its existing files gives PARTIAL (0.327 ratio), and the old status stays SUCCEEDED.
D4 Export and report (`export.py`). Every model -> `models/<i>/{sparse.ply,trajectory.json,model_report.json}`; top-level `sparse.ply`/`trajectory.json` remain the largest model for backward compatibility and are labelled `partial` when the verdict is not GOOD. `coverage.json`: for each selected frame -> `{model: i | null, timestamp_s, inliers_to_prev}`; plus a list of `missing_segments` (time ranges with no registered frame) and `jumps`. No cross-model merge anywhere. Exit: file counts match `num_models`; `replay.load_session` validates each model's PLY/poses against its own report.
D5 Callers (`server.py`, `replay.py`, `cli.py`, `app.js`, `tracking.js` untouched). Server session list adds `quality.verdict`; replay refuses nothing on PARTIAL but passes the label through; CLI exit code stays 0 on SUCCEEDED and prints the verdict; UI badge shows GOOD/PARTIAL/POOR instead of READY (READY is removed), a model selector labelled "partial: model i of N (k/M frames)", a coverage strip on the replay timeline (registered, unregistered, jump marks), and a fixed caption "SPARSE POINTS (SfM), not surfaces; RELATIVE scale; NOT_NAVIGATION_SAFE". Any relative-depth view stays in its own panel with a "not verified geometry" caption. Exit: UI smoke test asserts the badge text is one of GOOD/PARTIAL/POOR and that READY no longer appears.
D6 Regression tests. `tests/test_quality.py`: a fabricated report with ratio 0.33 is PARTIAL, never GOOD; a report with two models > 10 % is not GOOD; frames across a synthetic cut are never in one model's trajectory; `coverage.json` row count == selected frames. `tests/test_server.py`: session list exposes `quality.verdict`; `ui_smoke.mjs`: PARTIAL badge and model selector appear for a fixture session with 2 models.

## 3. Before/after protocol (run after D1–D5, numbers recorded by the implementer, not here)
Inputs: (A) Bangkok clip, same SHA-256 as the baseline; (B) one continuous moving-camera shot picked from `shots.json` of `data/public/yt_montreal_street/bwJ-TNu0hGM.mp4` (licence per its `SOURCE.md`), declared by start/end second before the run. Command: `python -m mapping.cli build <mp4> --session <id> --origin PUBLIC_DATASET --shot <start>-<end>`; seed 0; CPU. Record for before and after: selected frames, `max_gap_s`, num_models, model_sizes, registered_ratio, time_coverage, mean_reprojection_px, jumps, verdict, MAP time. PASS: (A) verdict reported as PARTIAL or POOR with per-boundary causes, never GOOD, and the UI shows it as partial; (B) verdict GOOD on at least one declared shot, or a recorded FAIL with the failing check named. Never lower thresholds to pass; a FAIL is logged in `docs/VALIDATION_LOG.md` and `docs/FAILURES.md`.

## 4. Acceptance criteria
1. No session with `quality.verdict != GOOD` is shown as a normal completion in CLI, server list, replay or UI.  2. Thresholds in this document equal the constants in the report.  3. Every model is exported separately; no merged geometry exists.  4. Bangkok diagnosis lists a confirmed cause (or `none_confirmed`) per model boundary.  5. Provenance fields unchanged (SHA-256, `data_origin`, licence note).  6. Existing tests still pass; new tests from D6 pass.

## 5. Risks and fallbacks
Per-shot COLMAP runs multiply MAP time (263 s for 150 frames on CPU): cap total selected frames per session at 400 and report the per-shot share. If the shot detector finds no cut in Bangkok and the causes are motion-related, the fix is denser frames inside the shot (target_fps 5, max_frames 300) tested as a separate declared run, not a threshold change. If the Montreal clip has no shot >= 20 s of translating camera, pick another CC BY clip and record its provenance first; own-camera capture remains optional.
