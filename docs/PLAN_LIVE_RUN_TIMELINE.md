# Plan — Live run on one time axis (file at original rate / webcam; detect + track + VO together) (2026-11-09)

Author: fable-planner (claude-fable-5-1). Implementer: Opus 5.5. Obeys `docs/VERIFICATION_CONTRACT.md`, `docs/RECOVERY_MATRIX.md`. Minimal change: reuse `vision.person_detector`, `tracking.tracker` (MultiTracker, TargetSelector), `control.yaw_controller`, `vision.vo.VisualOdometry`, the `status.json`/JobKind pattern of `vision.track_video` + `apps/desktop/server.py`, and the Tracking tab renderer. Labels everywhere: detector `REAL_MODEL`, VO `RELATIVE / no loop closure / NOT_NAVIGATION_SAFE`, commands `MOCK`, telemetry `VIRTUAL`, map position `NOT_AVAILABLE`. `HARDWARE_ARMED=false`; no sockets.

## Critique of the proposed direction (keep the shape, fix these)
1. Two clocks, named explicitly. `media_t` = source time (file: frame index / fps; webcam: capture wall time). `run_t` = monotonic wall seconds since run start (pauses included) and is the **single time axis** of `timeline.jsonl` and of `tracks.json` replay. The tracker, selector and YawController are driven by the **media clock** (`media_now`): file realtime = `media_t_at_resume + (wall - wall_at_resume)` while playing, frozen while paused; `--rate max` = timestamp of the frame being processed; webcam = wall. Frame age for STALE_FRAME = `media_now - frame.media_t`, so a decoder/camera stall is detected without extra code (YawController `max_frame_age_s=0.3`).
2. Seek and source change break monotonic `media_t`; the tracker rejects rewinds and VO segments must not be chained. Every seek increments an `epoch` and resets MultiTracker, TargetSelector (target cleared → operator must re-select), YawController and starts a new VO segment; event `SEEK{from,to,epoch}` is logged. **Switching video = stop this run + start a new run** (one source per run_report; the UI offers it as one button). Do not add multi-source runs.
3. `control.json` polling needs a sequence number: `{"seq": n, "op": ..., "args": ...}` written atomically by the server; the worker records `control_seq_applied` in `status.json` and the UI disables transport buttons until `applied >= sent` (prevents lost/duplicate seeks). Poll ≤ 50 ms. Ops: `pause`, `resume`, `seek{media_t}`, `stop`, `select{track_id}`, `clear`.
4. Scene changes: reuse VO's own detectors (histogram correlation / one-frame survival → `LOST` reason starts with `scene change`) as the `shot_change` flag; `mapping.shots` is an offline whole-file pass and is **not** run in the live loop (optional later for file pre-annotation).
5. `frames/`: write the processed frame downscaled to long side 640, JPEG q75, plus `frames/latest.jpg` by atomic rename for the live view; at realtime the worker will not reach 30 fps and that is expected — drops are the mechanism, not a bug. Record `frames_written` and a `frames_manifest` (name + size) in `run_report.json`.
6. Pause is not a controller decision: while paused the worker emits ≤ 2 Hz heartbeat rows `{frame: null, yaw: 0, stop_reasons: ["PAUSED"]}` without calling YawController (it is never asked for yaw with no frame). Likewise input stall rows `{frame: null, input_state: "STALLED", stop_reasons: ["STALE_FRAME(..)", "INPUT_STALL"]}` where STALE_FRAME comes from YawController and INPUT_STALL is appended by the worker. Non-zero yaw can only originate from `YawController.command` with `TargetState.LOCKED`.
7. Completion is binary and file-backed: `run_report.json` is written last; `status=SUCCEEDED` only when `timeline_rows == lines in timeline.jsonl`, `sha256(timeline.jsonl)` matches, and every manifest frame exists. Killed process → no run_report → server shows `INCOMPLETE` (reuse `_pid_alive` + `STALE_AFTER_S`), never SUCCEEDED. Cancel → `CANCELLED` with partial files readable.

## Interfaces (Opus implements; names are contracts)
- `packages/vision/live_source.py`: `class LiveSource(Protocol): meta() -> {kind, fps|None, size, path|index}; read() -> SourceFrame|None (None = no new frame yet); seek(media_t) -> bool (webcam: False); close()`. `FileSource(path, rate="realtime"|"max")` (reuses `mapping.frame_source.VideoFileSource` decoding; realtime sleeps to the file's time base) and `WebcamSource(index)`; `open_live("webcam:0" | path, rate)`. `LatestFrameBuffer`: 1 slot, `put()` returns True if it overwrote an unread frame (`dropped += 1`), `take(timeout)`.
- `python -m vision.live_run <source> --session X --rate realtime|max [--runs-root outputs/runs] [--model yolox_nano] [--fx F|--calib camera.json] [--vo-width 640] [--max-seconds N]`. Pipeline per taken frame: detector → `MultiTracker.update(media_t, dets)` → `TargetSelector.evaluate` → `YawController.command(media_now, state, track if LOCKED else None, frame.media_t, telemetry_t=media_now, battery=85)` → `VisualOdometry.process(media_t, resized)`. Test seam: `run_live(req, source: LiveSource, pipeline: Callable | None, cancel: Event)`; the pipeline can be replaced by a sleeping stub to prove drops without a model or device.
- `timeline.jsonl` row: `{row, epoch, run_t, media_t|null, wall_t, proc_ms, latency_ms (wall processed − wall captured), dropped_since_last, input_state: LIVE|PAUSED|STALLED|EOF, image|null, detections, tracks, target_id, target_state, yaw, stop_reasons, vo_state, vo_segment, T_world_camera|null, vo_reason, shot_change, events[]}`; append-only, `flush+fsync` every 10 rows and at every event. Header row 0 carries source reference (path/index, sha256 for files, fps, size), intrinsics provenance (`ESTIMATED|USER_GIVEN_FX|CALIBRATION_FILE`), labels, `map_position: NOT_AVAILABLE`, `relocalization: NOT_IMPLEMENTED`.
- `status.json` as in track_video plus `control_seq_applied, input_state, last_row, last_run_t, dropped_total, processed_total`. `run_report.json`: counts (captured, processed, dropped, rows, frames_written), `latency_ms{p50,p95}`, `proc_ms{p50,p95}`, processed fps, `yaw_nonzero_while_not_locked_or_stop` (must be 0), epochs, VO segments and `no_pose_spans` (`[{run_t0, run_t1, reason}]`), `scene_changes[]`, events, `timeline_sha256`, `frames_manifest`, `status`.
- `tracks.json` (same shape the Tracking tab reads; `t` := `run_t`, `k` := row index, extra `media_t`, `epoch`) so `control_replay` works unchanged on a finished run, labelled `OPEN_LOOP_REPLAY`; closed-loop simulation stays in `sim` and never reads live runs.
- Server: `JobKind("runs", outputs/runs, "run_report.json", {timeline.jsonl, run_report.json, tracks.json, status.json, frames/latest.jpg, frames/f%06d.jpg})`; `POST /api/run-jobs {source|input_id, rate}` (still one job at a time across maps/tracks/runs), `GET /api/runs`, `GET /api/runs/<id>` (session_state incl. `control_seq_applied`, INCOMPLETE rule), `GET /api/runs/<id>/files/<name>`, `POST /api/runs/<id>/control {seq, op, args}` → writes `control.json`, 409 if not running, `POST /api/run-jobs/<id>/cancel`, `POST /api/runs/<id>/replay` → existing `control_replay` over the run's `tracks.json`. Webcam source allowed only for `webcam:\d` strings; no arbitrary paths from the client (use `input_id` allow-list as today).
- UI: "Live" mode inside the Tracking tab (`tracking.js` state object `L`), polling `status.json` + `latest.jpg` every 250 ms: overlays (boxes, ids, states, selected target), badges input/epoch/processed fps/latency p95/dropped, target state + MOCK yaw + STOP reasons, VO state/segment and a 2D path panel titled **"VO path (relative scale, per segment, not a map)"** that breaks the line at `null` poses and segment changes and shades no-pose spans; `Map position: NOT_AVAILABLE`. Transport: pause/resume/seek(slider for files, disabled for webcam)/stop/switch video (= stop + new run). UI states: `STALE_DATA` (no new row for > 0.5 s while input_state LIVE), `PAUSED`, `STALLED`, `FAILED`, `CANCELLED`, `INCOMPLETE`, `RESTARTING` (status pid changed), `DISCONNECTED` (health poll fails). Finished runs open in the existing replay view as OPEN_LOOP_REPLAY.

## Milestones (each ends with raw evidence under `outputs/evidence/live/`)
- M1 live_source + buffer + clocks (unit tests). M2 live_run worker writing timeline/status/report, cancel, seek/epoch, completeness check. M3 server kind "runs" + control endpoint + replay reuse. M4 UI live mode + states + smoke. M5 end-to-end runs on a real clip (one `--rate realtime`, one `--rate max`) and the no-device webcam check.

## Acceptance tests (PASS / FAIL / BLOCKED / NOT_RUN; numbers measured on this Mac, not predicted)
- T1 buffer: producer at 100 Hz, consumer sleeping 50 ms → `dropped == captured − taken` exactly; no frame older than the latest is ever returned.
- T2 clocks: file `--rate realtime` on a 10 s clip finishes in 10 s ± 0.5 s; `media_t` of processed rows is strictly increasing within an epoch; pause 2 s → no frame rows, `media_now` frozen, ≥ 1 PAUSED heartbeat row; resume continues from the same `media_t`.
- T3 control: `seek` → next row has `epoch+1`, empty tracks, `target_state == SEARCHING`, VO `segment` incremented and `T_world_camera` identity/null; `control_seq_applied` reaches the sent seq within 200 ms; unknown op → ignored and logged, never crashes.
- T4 safety: stub pipeline with scripted tracks: AMBIGUOUS, PREDICTING, LOST, a 0.5 s injected input stall, and a paused span → `yaw == 0` with the expected reasons on every such row; `yaw_nonzero_while_not_locked_or_stop == 0` over the whole run; LOST stays LOST until `select` arrives.
- T5 persistence: SIGKILL mid-run → `GET /api/runs/<id>` says `INCOMPLETE`, timeline rows readable up to the last fsync; cancel → `CANCELLED`; completed run → sha256 and row count verified, `SUCCEEDED`; all previous `outputs/tracks/*` sessions still list and replay (regression).
- T6 webcam path: `webcam:0` with no device → `FAILED` with reason `NO_DEVICE` within 5 s, no partial SUCCEEDED; `FileSource(rate="realtime")` through the same `LiveSource` interface passes T1–T4 (this is the device-free proof; a real-webcam run is NOT_RUN unless a camera is attached).
- T7 end-to-end real clip (YOLOX-nano, VO 640 px, realtime): processed fps ≥ 8, `latency_ms p95 ≤ 250`, dropped count reported and equal to captured − processed, frames_written == processed rows, no-pose spans and scene changes listed, `tracks.json` reopens in the Tracking tab and `/replay` returns `OPEN_LOOP_REPLAY` with `nonzero_yaw_while_not_locked == 0`. Below the fps/latency figures → FAIL with numbers, not a relaxed threshold.
- T8 server/UI: endpoints status codes (202/200/404/409), path allow-list, 127.0.0.1 only; UI smoke covers LIVE, STALE_DATA, PAUSED, STALLED, FAILED, CANCELLED, INCOMPLETE, DISCONNECTED and the "VO path" panel label.

## Explicitly NOT_IMPLEMENTED in this iteration (state as such in UI and reports)
Map position / relocalisation into a stored map (requires 2D–3D correspondences + PnP inlier gating; a VO path is never drawn in a stored map's frame); loop closure; metric scale; any 3D person position from a 2D box; closed-loop simulation inside a live run; multi-source runs; Tello adapter; real-webcam measurement without a device.

## Fallbacks
Realtime cannot hold ≥ 8 fps → run VO at 480 px or every 2nd taken frame (record it in the header) before touching the detector. `cv2.VideoCapture` sleeping jitter > 50 ms → use a monotonic deadline scheduler, not per-frame sleeps. If the Tracking tab renderer cannot share state cleanly → a separate `live.js` with the same draw helpers; never fork the tracker/controller.
