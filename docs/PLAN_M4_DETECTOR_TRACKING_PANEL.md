# Plan M4 — Real person detector + tracking panel (2026-11-09)

Author: fable-planner (claude-fable-5-1). Implementer: Opus 5.5. Extends `docs/IMPLEMENTATION_PLAN.md` (M3, fallback F6); obeys `docs/VERIFICATION_CONTRACT.md`, `docs/RECOVERY_MATRIX.md` (YOLO row). User request: connect a real person-detection model and add a tracking panel to the web UI.

Environment facts (Opus audit): Apple M6, 16 GiB, CPU only; `.venv` has opencv-python-headless 5.0.0 (`cv2.dnn`), numpy, scipy; no torch/ultralytics/onnxruntime; network available; `assets/input/` empty. Existing: `tracking.tracker` (Detection.source REAL_MODEL|SYNTHETIC, MultiTracker, TargetSelector with no auto re-acquire), `control.yaw_controller` (yaw-only, STOP reasons), closed-loop SIMULATED scenario (M3-T1 PASS), stdlib server with subprocess jobs + `status.json`, canvas UI with 8 states (26/26 smoke).

Fixed decisions: model **YOLOX-nano ONNX (Megvii, Apache-2.0)**, local inference only, weights under `data/models/` (gitignored, `SOURCE.md` kept). Detector tiers, always visible in UI and reports: `REAL_MODEL` (YOLOX via cv2.dnn or onnxruntime) → `REAL_MODEL_LIMITED` (OpenCV HOG) → `SYNTHETIC`. Tracking runs **offline on video time** (deterministic); PID runs as **open-loop replay** over the recorded track timeline, no sockets. `HARDWARE_ARMED=false`, `DRY_RUN=true`; one job at a time across map and track kinds (16 GiB, CPU). Every result PASS / FAIL / BLOCKED / NOT_RUN with raw evidence under `outputs/evidence/m4/`.

## Changes to the proposed direction (Opus draft → this plan)
1. Add `onnxruntime` (Apache-2.0, arm64 wheel, project `.venv` only) as the middle fallback if OpenCV 5's DNN engine rejects the YOLOX graph; HOG is last, never first. Record the exact import error in `docs/FAILURES.md` before switching.
2. PID replay is **open-loop**: the recorded camera does not respond to the yaw command, so centering error never shrinks. Report sign correctness and STOP behaviour only; never a centering metric. Label `MOCK_OPEN_LOOP_REPLAY`. No MockTello/UDP in the replay path (closed-loop stays in `sim.tracking_scenario`).
3. Tracker clock = frame timestamp from the video (index / fps or TUM `rgb.txt`), not wall time; detector latency measured separately with `perf_counter`.
4. The tracking view is a **mode of the camera panel** with its own state object and session list; map frames/poses are untouched. Map console smoke (26/26) is a regression gate.
5. `track_video` accepts `--detector synthetic` (scripted boxes, purple SYNTHETIC) so job/UI/replay tests do not depend on downloaded weights; those PASS rows never count as real detection.
6. Primary test data: TUM `fr3_walking_xyz` (CC BY 4.0, same download/SOURCE.md pattern as fr1/desk, people are the dataset authors). OpenCV `vtest.avi` only if its footage provenance is documented in the OpenCV repo; otherwise skip and record why.
7. Verify YOLOX preprocessing against the tagged release used (later releases dropped mean/std normalisation; BGR, letterbox pad 114, 416×416, outputs `[1, 3549, 85]` raw grid). Record conf 0.3 / NMS IoU 0.45 (repo demo defaults) in the report header.
8. The UI reads `status.stages` from the server instead of the hard-coded map STAGES map, so one job renderer serves both kinds.

## Interfaces
- `packages/vision/person_detector.py`: `class PersonDetector(Protocol): name: str; tier: str; input_size; def detect(self, bgr: np.ndarray) -> list[Detection]`. `YoloxOnnxDetector(weights, backend="cv2"|"ort", conf=0.3, nms_iou=0.45, size=416)`, `HogDetector()`, `SyntheticScriptDetector(script)`. `load_detector(spec: str) -> PersonDetector` tries `yolox-nano:cv2` → `yolox-nano:ort` → raises; `hog`, `synthetic` explicit. Detections: class 0 only, `source="REAL_MODEL"` for YOLOX and HOG (tier distinguishes LIMITED), `"SYNTHETIC"` for scripted.
- `packages/vision/yolox_postprocess.py` (pure numpy, no cv2): `letterbox(img, size) -> (padded, ratio, (dx, dy))`, `decode_grid(raw, size, strides=(8,16,32)) -> xyxy+scores`, `nms(boxes, scores, iou)`, `unletterbox(boxes, ratio, offset)`.
- `python -m vision.track_video <video|frames_dir> --session X --detector yolox-nano|hog|synthetic [--stride N --max-frames M --fps F --tracks-root outputs/tracks]`. Writes `outputs/tracks/X/{status.json, tracks.jsonl, tracking_report.json, frames/f%06d.jpg, process.log}`. `status.json` keys identical to the map job (`state, stage, stage_index, stages=[DECODE, DETECT_TRACK, EXPORT], progress, message, pid, started_at, updated_at`); SIGTERM → `CANCELLED`, partial files kept.
- `tracks.jsonl`: line 0 header `{"header":true,"label":"REAL_MODEL|REAL_MODEL_LIMITED|SYNTHETIC","detector":{name,backend,weights_sha256,license,input_size,conf,nms_iou},"input":{path,sha256,origin,fps_nominal,stride,image_size},"tracker_config":{...}}`; then per frame `{"i","t","image"|null,"detect_ms","dets":[[x1,y1,x2,y2,score],...],"tracks":[{"id","state","bbox","cx","cy","sigma_px","hits","age_s"}]}`.
- `tracking_report.json`: header fields + `timing{detect_ms_p50,p95,track_ms_p50,p95,end_to_end_fps}`, `tracks{created,lost,max_concurrent,mean_len_s,id_churn_per_min,frames_with_detection_ratio}` (labelled `"proxy_only": true`), `metrics{"MOTA":null,"IDF1":null,"note":"undefined: no ground-truth boxes"}`, `status`, `commands[]`, `created_at`.
- `packages/vision/replay.py`: `replay_yaw(tracks_path, target_id, select_at_index, image_width, faults=None) -> dict` — pure function; iterates recorded frames, `TargetSelector.select` at `select_at_index`, `YawController.command(now=t_k, frame_t=t_k or last unfrozen t, telemetry_t=virtual 10 Hz, battery=85)`. `faults` (all labelled injected): `frozen_frames=[(i0,i1)]`, `telemetry_gap=[(i0,i1)]`, `battery_pct`. Output `{"label":"MOCK_OPEN_LOOP_REPLAY","target_id","select_at_index","frames":[{"i","t","target_state","rc_yaw","stop_reasons"}],"summary":{"frames_locked","nonzero_yaw_when_not_locked","sign_agreement_ratio","hardware_packets":0,"udp_sockets_opened":0}}`. Cached to `outputs/tracks/X/replay_<target>_<i>.json`.
- Server (`apps/desktop/server.py`): `GET /api/tracks`, `GET /api/tracks/<X>`, `GET /api/tracks/<X>/files/{tracks.jsonl,tracking_report.json,frames/f%06d.jpg,replay_*.json}`, `POST /api/jobs {"kind":"track","input_id","detector","stride","max_frames","session"}` (existing `kind` defaults to `"map"`), `POST /api/jobs/<sid>/cancel` unchanged, `POST /api/tracks/<X>/replay {"target_id","select_at_index","faults"?}` → 200 JSON. Same `SESSION_ID` regex, path allow-list, 127.0.0.1 only, one running job.
- UI (`apps/desktop/static/`): camera panel gets a mode switch **Map frames | Tracking**; tracking mode = `<canvas>` over the frame JPEG (boxes, id, state colour), track list (id, state, age, score, sigma), target badge SEARCHING (offline) / LOCKED (ok) / PREDICTING (warn) / LOST (error), detector badge `REAL_MODEL · yolox-nano` (real/blue), `REAL_MODEL_LIMITED · HOG` (warn), `SYNTHETIC` (sim/purple), PID readout `rc yaw <n> · MOCK_OPEN_LOOP_REPLAY` + STOP reasons, scrubber/play reusing the transport, new states `NO_TRACKS`, `LOADING_TRACKS`, `TRACKING_JOB_RUNNING`, `FAILED`, `CANCELLED` via existing badge/notice tokens. Keys: `1/2/3` select the 1st–3rd track of the current frame (sorted by id, announced), `0` clear target, `T` toggle mode; no key sends drone commands.

## Acceptance (all write `outputs/evidence/m4/`)
- M4-T1 postprocess units: PASS iff decode/NMS/letterbox tests pass with fixed tensors (no model needed).
- M4-T2 real detector smoke: PASS iff YOLOX loads (cv2 or ort), runs on ≥ 50 fr3 frames, `frames_with_detection_ratio ≥ 0.5` (weak gate, chosen before running, this sequence has people in most frames), detect_ms p50/p95 recorded; weights missing → BLOCKED naming the file; graph load fails on both backends → FAIL + F-xx entry, HOG run recorded as `REAL_MODEL_LIMITED`, never as the YOLOX PASS.
- M4-T3 tracking job: PASS iff `tracks.jsonl` header + ≥ 1 frame line validate against the schema, `tracking_report.json` has `MOTA=null, IDF1=null` with the note, `status=SUCCEEDED`; cancel mid-run → `CANCELLED`, partial files kept; synthetic run labelled SYNTHETIC and refused if requested as REAL.
- M4-T4 replay: PASS iff `nonzero_yaw_when_not_locked == 0`, `sign_agreement_ratio ≥ 0.9` over LOCKED frames with |error| > 0.1 (open-loop saturates to the error sign), injected freeze → `STALE_FRAME` STOPs, LOST never re-locks without a new `select`, `udp_sockets_opened == 0` (monkeypatched `socket.socket` raises).
- M4-T5 server: PASS iff all new endpoints covered (404 on bad session/file, 400 on bad body, 409 when a job of either kind runs), `hardware_armed=false` unchanged.
- M4-T6 UI: PASS iff extended smoke passes with 0 console errors and the original 26 checks still pass.
- M4-T7 unarmed guard: PASS iff `vision.track_video`, `vision.replay` and the server import no `adapters.tello` symbol that opens a socket, asserted by test.
- M4-T8 provenance: PASS iff both `SOURCE.md` files list URL, licence, size, sha256, and `git status` shows no weights or dataset files staged.

## Risks and fallbacks
- R1 OpenCV 5 DNN rejects YOLOX ONNX (new engine, Focus/slice ops) → check for an engine/legacy option in `help(cv2.dnn.readNetFromONNX)`, else onnxruntime in `.venv`, else HOG LIMITED; log first.
- R2 Release URL/tag changed → try the pinned release tag list in the repo; never use an unofficial mirror; BLOCKED if none.
- R3 CPU latency high → stride 2–3, input 320 (recorded in header), tiny→nano; job is offline so the UI is unaffected.
- R4 Many false positives → `conf` 0.3→0.5 only as a recorded config change; no tuning to hit the T2 ratio.
- R5 Memory → stream frames, never hold the video; JPEGs long side ≤ 640.
- R6 UI regression → tracking mode isolated in `tracking.js`; the 26 map checks gate the merge.
- R7 Privacy → dataset authors only; ids are session-local integers; no face crops, no Re-ID, no external upload.

## Safety constraints (explicit)
No identity re-identification or appearance model; new id after LOST. No distance or approach from bbox size; lateral/forward/vertical stay 0. No hardware: replay and job open no sockets; `TelloClient` untouched; `HARDWARE_ARMED=false`, `DRY_RUN=true`; UI keeps `NO REAL DRONE`. Open-loop replay is labelled as such and never presented as tracking performance. Model inference local only; no paid API. Real vs LIMITED vs SYNTHETIC labels on every report, badge and PASS row.
